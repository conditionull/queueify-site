Mods, and any viewers you whitelist, can move the widget from Twitch chat, which is useful when
it covers something in the game.

`!topright set` and `!bottomcenter set` require an OBS WebSocket connection. Two steps, and only
the first is in OBS.

::steps{level="3"}

### Turn the WebSocket server on

**OBS → Tools → WebSocket Server Settings**, then **Show Connect Info**.

### Paste the connect info into the dashboard

Open the **OBS** step at `http://127.0.0.1:3002` (or run `npm run setup` if the bot is not
running), paste the connect info, and pick your scene and the widget source from the dropdowns.

::

The scene and source lists come from OBS itself, so they are dropdowns on the dashboard rather
than names you type. Changing them later takes effect on the next command, without stopping the
bot.

## Who can move it

Mods always can. Viewers who are not mods go in **Admin Panel → Settings → Whitelist**.

## The two presets

::presets-diagram
::

::note
The names are labels only. `!topright` and `!bottomcenter` are two positions you can set
anywhere, so `!topright set` can be the bottom left.
::

| Command | Who | What it does |
| --- | --- | --- |
| `!topright set` / `!tr set` | Mods | Save the widget's current position as the first preset |
| `!topright` / `!tr` | Mods and whitelisted viewers | Move the widget to that preset |
| `!bottomcenter set` / `!bc set` | Mods | Save the second preset |
| `!bottomcenter` / `!bc` | Mods and whitelisted viewers | Move the widget to that preset |

Both presets also have buttons in the theme editor, so you can place the widget without using
chat.

## Positions are per theme

`!tr set` on one theme does not affect another. Switching theme, by hand or because the OBS
scene changed, puts the widget back where that theme was positioned.

You do not have to use the commands at all. Queueify remembers where each theme's widget last
was on the canvas, so dragging it into place in OBS survives switching theme and switching back.
`!tr` or `!bc` overrides that with the position you saved.

## When a saved position stops working

A saved position survives a theme being **resized**. It does not survive a theme changing
**shape**: it no longer fits the space it was set in, so Queueify keeps it in the same corner at
a size you did not choose. The editor warns you and asks you to run `!tr set` / `!bc set` again
once the layout is final.

::note
A position is stored as a rectangle, not a scale. A scale is only meaningful against the source
size it was measured at, and that size changes with every theme.
::
