## The three ports

| Port | What is on it |
| --- | --- |
| `3001` | The widget, which is your OBS browser source URL |
| `3002` | The dashboard |
| `3000` | The Canvas video helper |

If the widget's or the Canvas API's port is taken, queueify names it and stops. Usually that
means queueify is already running in another window. A dashboard already serving on its port is
reused.

## Changing them

The dashboard is served on one of these ports, so it cannot change them. Put them in `.env` if
the defaults clash with something else:

```ini [.env]
SETUP_PORT=3002            # the dashboard
QUEUEIFY_WIDGET_PORT=3001  # the widget, i.e. your OBS browser source URL
QUEUEIFY_CANVAS_PORT=3000  # the Canvas video helper
```

The dashboard link printed at startup, and the address queueify puts in chat messages, both
follow `SETUP_PORT`.

## What else is in `.env`

The dashboard fills this in. It is listed here so you know what is on disk.

```ini [.env]
TWITCH_BROADCASTER_USERNAME=
TWITCH_BOT_USERNAME=

SPOTIFY_CLIENT_ID=
SPOTIFY_CLIENT_SECRET=
SPOTIFY_REDIRECT_URI=http://127.0.0.1:8000/callback

OBS_WEBSOCKET_PASSWORD=
OBS_WEBSOCKET_PORT=4455
OBS_WEBSOCKET_IP=127.0.0.1
OBS_SCENE=
OBS_SOURCE=

SP_DC=
```

::note
`OBS_*` and `SP_DC` are re-read while the bot runs, so a change here, or on the dashboard, takes
effect on the next command.
::

::warning
`OBS_SCENE` and `OBS_SOURCE` have to match the names in OBS exactly. Typing them by hand is the
most common reason `!tr` and `!bc` fail; pick them from the dashboard dropdowns instead.
::

## Overrides for contributors

Every path queueify writes to can be pointed somewhere else, which is how the test suite runs
without touching real data:

`QUEUEIFY_DATA_DIR`, `QUEUEIFY_THEMES_DIR`, `QUEUEIFY_SETTINGS_FILE`,
`QUEUEIFY_USER_SETTINGS_FILE`, `QUEUEIFY_WIDGET_CONFIG_FILE`, `QUEUEIFY_SCENE_THEMES_FILE`,
`QUEUEIFY_HISTORY_FILE`, `QUEUEIFY_ALIASES_FILE`, `QUEUEIFY_MESSAGES_FILE`,
`QUEUEIFY_COMMANDS_DIR`, `QUEUEIFY_CHANGELOG_FILE`, `QUEUEIFY_LUCIDE_DIR`,
`QUEUEIFY_ENV_FILE`, `QUEUEIFY_WIDGET_URL`

::caution
These are read when a module is first loaded, so they have to be set **before** the module is
required. Setting one after the fact writes to your real project.
::
