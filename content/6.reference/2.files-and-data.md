Everything queueify stores is in the project folder. There is no database and no server.

| File or folder | What it holds |
| --- | --- |
| `.env` | Twitch and Spotify credentials, OBS connection, `sp_dc` |
| `spotify-token.json` / `twitch-token.json` | Access and refresh tokens, managed for you |
| `queue-settings.json` | Cooldown, maximum length, repeat delay, and widget positions |
| `queue-state.json` | Whether the queue is open |
| `queue-blacklist.json` | The deny list |
| `queue-pending.json` | Songs queued but not yet played, reconciled against Spotify |
| `queue-history.jsonl` | Every request ever made, for the stats page |
| `widget/themes/` | Your themes |
| `config/aliases.json` | Command names and aliases |
| `config/messages.json` | Every line queueify says |
| `config/settings.js` | Defaults; created for you if missing |

All of it survives an update. The three built-in themes are read-only and get replaced; themes
you made or imported are left alone.

::note
`queue-settings.json` is written the first time you set a value with `!delay`, `!duration` or
`!repeatdelay`. Until then the defaults apply.
::

## How a widget position is stored

As a rectangle, not a scale. A scale is only meaningful against the source size it was measured
at, and that size changes with every theme, so queueify stores the rectangle and recalculates
the scale each time.

::tip{to="/obs/moving-the-widget"}
Why a theme that changes shape needs its position set again.
::

## Themes

A theme is a folder under `widget/themes/`. Updates do not touch the ones you made, and new
fields in the theme model ship with a fallback, so a theme you already saved keeps rendering the
same way.

## Network access

queueify talks to Twitch and Spotify, and to the Canvas helper only when a theme asks for a
clip. The dashboard and stats page bind to `127.0.0.1` only.
